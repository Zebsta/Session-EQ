# Аудиосессии и работа в фоне

## Обработка звука

Session EQ использует Android DynamicsProcessing: 20 полос предварительного EQ,
входное усиление для предусиления и баланса, а также необязательный связанный
стереолимитер. Аудиоданные не захватываются и не воспроизводятся заново приложением.

Rock со скриншота и `AIMP Windows · Rock` — разные наборы числовых значений.
Совпадение усилений и частот не означает совпадения АЧХ с AIMP.
AUTO компенсирует запас по уровню, а не выбирает пресет по жанру.

## Получение сессий

Основная интеграция — Android-события OPEN/CLOSE и вызов панели внешнего
эквалайзера проигрывателем. ID сессии временный: новые события используют
новые ID, а при закрытии эффект освобождается.

Поиск по запросу использует `android.permission.DUMP`, выданное через ADB.
Сначала читается AudioService. Если прошивка требует дополнительные системные
права или возвращает неизвестный формат, используется `media.audio_flinger`.

Дамп читается через канал в памяти с одновременным чтением и записью, пределом
2 МиБ и ожиданием до пяти секунд на источник. Полные дампы не сохраняются
и не отправляются. Временные рабочие потоки завершаются после простоя.

Принимаются только текущие активные музыкальные выходные потоки с известными
UID и ID сессии. Исторические журналы, записи, системные звуки, другие профили
пользователей и неоднозначные shared UID не используются. Видимость пакетов
ограничена приложениями с launcher-активностью и явным исключением AIMP;
QUERY_ALL_PACKAGES не запрашивается.

AIMP блокируется при поиске, входящих событиях, открытии панели, сохранении
сессии и создании нативного эффекта. Дополнительные разрешения маршрутизации
звука не запрашиваются. DUMP не нужен для обычных событий от плеера.

## Автоподключение

Чекбокс «Авто» сохраняет имя пакета. При ON служба ожидает OPEN от выбранных
приложений с тихим постоянным уведомлением. CLOSE освобождает эффект;
последующий OPEN подключает актуальную сессию. Ручное подключение по строке
плеера доступно независимо от его отметки.

После снятия отметки новые автоматические подключения прекращаются, текущее
остаётся до закрытия сессии или OFF. Отмеченные приложения видны в списке
даже без воспроизведения. AIMP выбрать нельзя.

## Жизненный цикл и энергопотребление

- При OFF эффекты и foreground-служба освобождаются, отметки сохраняются.
- При ON без отметок «Авто» служба удерживается только пока существуют эффекты.
- При ON с отметками служба остаётся в ожидании даже без эффектов.
- Пауза, не закрывающая сессию, сохраняет подключение для возобновления.
- Нет периодического опроса, wake lock, доступа к микрофону или сети.

Служба ожидания запрашивает восстановление после выгрузки процесса, но Android
может её остановить. Если службы нет, событие от плеера может показать уведомление
с предложением подключения нажатием. После force-stop или перезагрузки открой
приложение снова: загрузочного receiver в проекте нет.

При отсутствии CLOSE от плеера полное освобождение доступно через OFF или
«Остановить службу». Расход батареи не измерен: учитывать нужно и обработку
в системном аудиопроцессе, а не только процесс Session EQ.

## Сообщения о сбоях

Интерфейс показывает краткие статусы без ID и технических отчётов.
Причины реальных ошибок остаются в Android logcat с тегом `SessionEQ`.
Журнала сессий в памяти приложения нет.
